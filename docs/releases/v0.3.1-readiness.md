## Design assessment and result

The original README led with a full three-terminal example before installation,
then mixed command reference, agent integration and detailed OAuth configuration.
Its real order comparison was useful but buried in the walkthrough.

The [Bend reference](https://github.com/bendlang/bend) was read as source and rendered
page text; its light/dark hero GIF frames were inspected separately. It uses a
strong identity, demonstrations near claims, short purposeful sections and direct
installation. Graybox adopts those principles with its own restrained centered
hero, an authentic output excerpt, a small command table and links grouped by
reader intent. No Bend media, branding, wording or benchmark claims were copied.

The new sequence is hero → demonstrated difference → why → installation → workflow
and capabilities → authenticated exercise → coding agents → documentation/community.
Detailed OAuth rules remain in the configuration guide. The CLI's independent
value precedes the separate instruction package. The demonstration is an original
1.5 KiB SVG; [provenance](../assets/README.md) records its source and interpretation.
Its text comes from actual output, not an invented terminal image.

## Vulnerability finding and release gate

The additional pinned scan failed with the default Go 1.27.3 toolchain:

```bash
go run golang.org/x/vuln/cmd/govulncheck@v1.8.0 ./...
```

It reported `GO-2026-6859`, an HTTP/1 server crash due to a MaxBytesReader header
race in `net/http`. The [official Go record](https://vuln.go.dev/ID/GO-2026-6859.json),
published November 11, lists fixes in Go 1.26.11 and 1.27.4. No other imported
package/module vulnerabilities were reported. These patched-toolchain checks passed:

```bash
GOTOOLCHAIN=go1.26.11 go run golang.org/x/vuln/cmd/govulncheck@v1.8.0 ./...
GOTOOLCHAIN=go1.26.11 go test -count=1 ./...
GOTOOLCHAIN=go1.26.11 go build ./...
```

The patched scan reported no vulnerabilities. go.mod still selects 1.26.10 and
CI reads that file; this documentation PR does not remediate CI/toolchain
selection or rebuild published binaries. Resolve the toolchain gate in separately
scoped work before tagging. Historical reports of earlier clean scans remain
accurate observations of their dates and are not rewritten.
