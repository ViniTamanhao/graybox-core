# Graybox v0.3.0

Release candidate notes — **not yet published**. Latest published release verified
2026-11-10: v0.2.3. This scope is based on `v0.2.3..0f5258f`, including merged
PRs #19, #21 and #23–#27, plus release preparation. No new CLI feature is added
by the preparation PR.

## Highlights and additions

- A documented agent verification contract and workflow: interpret nonempty
  equivalent, changed, failed and missing evidence without confusing HTTP errors
  with transport failures.
- A portable Codex skill under `skills/graybox`, installable into an independent
  application's `.agents/skills/graybox`. It guides baseline provenance, safe
  execution, private reports and command-grounded conclusions.
- Disposable skill, failure-handling and end-to-end development evaluations.
  Nine bounded end-to-end sessions passed 267 acceptance checks across ordinary
  tools, CLI, and CLI-plus-skill conditions. Skill sessions supplied more
  historical evidence; controls also succeeded. Improved final correctness was
  **not established**. See the [full evidence and limitations](../agent-end-to-end-evaluation.md).

Recording, inspection, sequential replay, semantic diff, JSON output, runtime
credentials and configurable redaction already existed in earlier releases.
They are the foundation of this workflow, not new v0.3 features.

## Improvements

- Authenticated change/restore examples and CLI contract/failure coverage,
  including incomplete evidence, empty results and failures after side effects.
- Release packaging verifies six archives, checksums, embedded versions and
  native help/startup before publication, with Linux/macOS/Windows smoke gates.
- Clearer installation, security boundaries, external-project skill installation
  and pinned CLI/skill guidance. The existing fixture can test an extracted CLI.
- Minimum Go version updated to 1.26.10; YAML dependency updated to v3.0.5.

## Fixes since v0.2.3

- Preserve the final HTTP response after informational responses such as 103
  Early Hints, including an implicit final 200.
- Refuse recognizable unreplaced credential markers in supported JSON/form/query
  fields before sending requests, including legacy recordings and partial
  replacements. Literal marker values are also refused deliberately.
- Preserve future evaluation report files across trial namespace teardown.
  This evaluator fix does not recover the first campaign's lost raw reports.

## Compatibility and security

Existing CLI commands/options, JSON structures, numerical exit-code meanings,
strict configuration syntax and schema-1 recordings remain supported. Diff exit
0 means equivalent **or empty**, 1 means changed without failures, and 3 means
at least one failed comparison. Replay retains its single/multiple failure
semantics. See the [contract](../agent-verification-contract.md).

Source builds require Go 1.26.10 or newer; prebuilt binaries need no Go toolchain.
The module remains `github.com/ViniTamanhao/graybox-core`. Recordings are read-only
during inspection/replay/diff; there is no automatic migration.

Mandatory header redaction and configured protections remain enforced. Runtime
credentials are not written back into recordings. The marker refusal and Go
security update are included; neither makes arbitrary recordings or reports safe
to share. Unconfigured values, URL paths and transformed secrets can remain.
Keep artifacts private and review before sharing. See [Security](../SECURITY.md).

## Known limitations

- Selected historical exchanges cannot guarantee regression-free applications
  or cover unrecorded behavior. Protected and ignored values are outside comparison.
- Replay and diff send real requests, potentially repeating writes. Use authorized
  disposable environments with external integrations disabled; loopback is not
  isolation. No rollback, automatic state reset or general stateful correlation.
- Skill installation does not guarantee automatic activation or correct agent
  reporting. No general improvement in coding-agent correctness is established.
- Command errors remain text diagnostics; no typed JSON error envelope exists.
- Binaries are not signed or notarized. Checksums do not authenticate a compromised
  distribution source. Some architectures are cross-built, not natively executed.

## Installation after publication

Do not run these versioned download/install commands until the maintainer publishes
v0.3.0. Before then, use the [candidate packaging procedure](../installation.md).

```bash
go install github.com/ViniTamanhao/graybox-core/cmd/graybox@v0.3.0
graybox version --json
```

Or download the native archive and SHA256SUMS from GitHub Releases. Names are
`graybox_0.3.0_OS_ARCH.tar.gz` (Linux/macOS) or `.zip` (Windows), with OS `linux`,
`darwin`, `windows` and architecture `amd64` or `arm64`. Verify the checksum before
extracting. Each archive contains only `graybox` or `graybox.exe` at its root.

Install the skill from the **same v0.3.0 repository tag**, following the
[skill guide](../agent-skill.md). The CLI archives do not contain the skill.
Tagged source distribution is sufficient for this small instruction-only package;
a separate skill archive adds no runtime capability and is deferred.
