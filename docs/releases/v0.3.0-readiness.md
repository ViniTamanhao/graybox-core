## Workflow audit

The unchanged release workflow triggers on `v*`, validates its documented
`vMAJOR.MINOR.PATCH[-PRERELEASE]` syntax, fetches main and requires the tag commit
to be an ancestor of main. It uses go.mod, runs Go tests/vet, packages six targets,
verifies archives/native Linux execution, and transfers artifacts to macOS and
Windows smoke jobs. Publication requires both build and smoke jobs, then rechecks
checksums. Failed prerequisite jobs prevent release creation. Incomplete build
outputs are not published; a GitHub upload/network failure could still leave a
partial release and must be inspected by the maintainer before retrying.

Permissions are `contents: write` at workflow scope (needed by publication, also
inherited by build/smoke). No additional permissions were added. Normal CI uses
read-only contents, three OS test/build/native-package jobs, plus Linux race and
vulnerability checks. Release itself runs tests/vet, not race/vulnerability scans;
maintainers must require green main CI before tagging. Notes are auto-generated;
append the reviewed release notes after publication. Hyphenated versions are
marked prerelease. No release workflow, tag, merge or publication was triggered here.
